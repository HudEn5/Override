# 原地转向角速度规划

当前实验版本`2.0.6-route3`。作用于高速X测试的TURN和正式路线的`Turn`、`TurnToHeading`；
原低速Test构建保留原角度PD，圆角、直行和机构控制保持各自逻辑。
自动路线沿用turn2转向参数，自动A为1500mm直行→原地90°→1500mm直行；下文turn1/turn2结果是各阶段的验证记录。
当前route3自动取消额外停稳计时，零速/到位门槛仍需满足，X单项保持250ms；下文250ms默认值与既有实车数据对应独立测试。

## 控制过程

1. 启动时按相对转角、最高电机rpm、角加速度和角减速度生成从静止到静止的角度/角速度参考。
2. 长角度形成加速—匀速—减速梯形；短角度自动降低峰值，成为三角形。
3. 由参考角速度产生左右等速反向轮速，再按参考角度和惯导实际角度的误差修正。
4. 按实际剩余角度及制动响应预留，额外限制朝终点运动的速度；两侧轮速继续使用原前馈和速度PID。
5. 参考结束后继续修正实际角度，满足原0.8°、轮速/角速度及250ms持续停稳要求才DONE。

角度参考是时间规划，实际轨迹会受负载和响应影响，不能把规划时长当成实际动作时长。
控制器由原主线程更新，电机仍由main统一写；没有增加线程，共享状态仍使用原mutex快照。
取消、禁用、传感器/电机离线、过期采样和超时会按原逻辑撤输出。

## 参数入口

修改`include/performance-config.h`中的`RouteTurnControl()`，保存后重新编译下载。

| 参数 | 当前值 | 单位及影响 |
| --- | --- | --- |
| `ROUTE_TURN_RPM`实验值 | 540 | 单侧电机减速箱输出轴rpm上限，轮端450rpm |
| `angular_acceleration_deg_s2` | 900 | 度/秒²，增大允许更陡的角加速 |
| `angular_deceleration_deg_s2` | 1200 | 度/秒²，增大允许更陡的角减速，也会缩短模型制动距离 |
| `profile_braking_delay_ms` | 120 | 实际剩余角度的制动预留；增大提前制动，减小需实车确认制动能力 |
| `kP` / `kD` | 3.0 / 0.10 | 规划角度误差与角速度误差修正，输出单位沿用电机rpm |
| `profile_finish_kP` | 6.0 | 仅参考结束后使用的角度纠偏增益；0沿用规划跟踪P |
| `minimum_settle_rpm` / `minimum_finish_rpm` | 50 / 30 | 仅参考结束后的低速补角，不作用于规划加减速段 |
| `minimum_rate_deg_s` | 32 | 低于32°/s完整保留补角最低转速，32～64°/s逐渐退出，避免高速补偿 |
| `AUTO_SETTLE_MS` | 0 | 自动到位且零速门槛满足即交接；100恢复route2、250恢复route1，X单项不受影响 |

**启用规划后，旧`acceleration_rpm_s=640`不再控制转向斜率**，改上表角加速度/角减速度。
两个角加减速度独立生效；提高数值不代表实车必能跟上，也不保证总用时一定更短。

现有2.75英寸轮、30:36外部传动、325mm轮距：

```text
角速度(deg/s) = 单侧电机rpm × 6 × 69.85 / 1.2 / 325
             ≈ 单侧电机rpm × 1.0746
```

540电机rpm对应规划角速度上限约580.3°/s；90°在当前900/1200角加减速下是三角形参考，
参考峰值约304.3°/s（283.1电机rpm），规划约592ms。
实际轮速还受制动包络、角度跟踪和负载限制，短弯达到不了540rpm是正常情况。

## 回退

- `TURN_FAST_FINISH=false`：只恢复首轮turn1补角（末端沿用P3、最低30/24rpm、低速权重阈值16°/s），角速度规划仍启用。
- `TURN_ANGULAR_PROFILE=false`：单独退回这轮改动前的540rpm上限、角度P2/D0.25及640rpm/s方案。
- `EXPERIMENTAL_FAST_ROUTE=false`：关闭整套实验提速副本，采用原共用基线速度及控制参数。
- 改动前源码、参数和二进制保留在本地忽略的`build/backups/before-turn-profile-20261116`。
- 本次末端优化前的turn1源码及当时构建产物在`build/backups/before-turn-finish-20261116`。

## 实车测试与数据

操作者从VS Code下载，核对版本`2.0.6-route3`，等惯导校准结束。
菜单X进入测试，上/下选TURN，右/左选择正负方向，A开始、B取消，Y切换回传。
默认90°，修改`high-speed-config.h`的`result.turn_deg`可测试30/120°；
`HIGH_SPEED_CORNER_DEG`控制的是圆角角度，和TURN不同。

采集继续使用`monitor-drive-websocket.mjs`，保持原2Hz精简频率和LOG开关：

- `-turn.csv` / DTN：实际角度、角速度、最终角度误差、轮速目标和状态，原11字段保留。
- `-turn-profile.csv` / DTA：规划参考角度/角速度、规划时长、峰值、阶段和跟踪误差。
- DTA阶段0未更新、1加速、2匀速、3减速、4参考结束后纠偏。三角形曲线跳过匀速；短动作可能被2Hz回传跳过部分阶段。
- `-velocity.csv`：左右速度误差及补偿，和上面数据按sequence对应。

## turn1软件验证边界

108组正反30/90/120°、0/900额外摩擦、0.9/1.0/1.1倍实际轮距、三组左右响应模型均DONE：
相对于改动前P2/D0.25/640rpm/s方案，平均2754→1556ms，最大终点0.784°，最大过程过冲0.859°。
标准90°模型3260→1900ms，实际峰值约219电机rpm，过程过冲0.12°。
原18组摩擦模型新候选平均1507ms；另验证±0.5/5/180/360°、低速上限、参考斜率、路线衔接和故障撤输出。

纯时间参考的初选在响应变化模型中曾过冲22°，已加入实际剩余角度制动限制后重跑。
以上均为软件模型，不能代替实车打滑、惯性与电池变化下的验证；首轮实车结果见下节，其他角度及负载尚待验证。

## turn1首轮90°实车数据

2026-11-16采集`drive-websocket-1794843560152`，记录四次新转向，排除采集开始时重复发送的旧DONE。
顺时针第二次DONE为1894ms/误差-0.72°，逆时针两次为1582ms/+0.20°和1583ms/+0.13°。
顺时针第一次只采到1613ms的运行态，误差-0.33°，随后开始下一次，未捕获其终态，不能计作完整DONE。
所有记录的参考时长591.6ms、峰值304.26°/s，确认新规划数据已回传；不是四次完整终态验收。
两次逆时针在732～771ms时仍差6.66～7.09°，1232～1272ms时进入角度窗口，之后停稳才DONE。
2Hz记录无法确定真实峰值或过冲最大值，后续提速重点需同时查看起转跟踪滞后、末端补角和停稳，而非只看最高rpm。

## turn2末端补角优化

实车尾段曾在还差6.66°时只要求17.15电机rpm，补角最低转速又会随角速度退去。
现在参考结束后单独使用P6，规划段仍P3；补角最低转速提高到50/30rpm，低速权重阈值提高到32°/s，
使低速跟进更连贯。保持原900/1200角加减速、120ms制动预留、0.8°角度窗口及250ms停稳要求。
两版在参考结束前对相同反馈的轮速和电压输出已逐周期核对一致。

对同一108组负载/轮距/响应模型，turn1→turn2平均1556→1345ms，
最后6°到DONE平均841→705ms；最大终点0.758°、过程过冲1.136°，全部DONE。
标准90°为1900→1520ms，最后6°到首次进入角度窗口360→200ms，到DONE为840→720ms。
这些为软件模型，本次候选尚待实车确认；没有用放宽容差、缩短停稳或延长超时来取得提速。

测试仍用X→TURN→左右选方向→A；每次DONE后等1秒再下一次，让2Hz采集有机会记录终态。

## turn2首轮八次90°实车

2026-11-17采集`drive-websocket-1794844921676`，逆时针/顺时针各四次，全部有完整DONE。
逆时针平均1400ms，顺时针1470ms；终态惯导误差最大0.40°。用户仍反馈单次看着不准，未提供外部角度测量，不能以回传替代物理验收。
每次相对转向以当次实际角度为起点，首次起点约1.59°，八次往返最后3.28°，累积约1.69°。
逆时针平均略多转0.28°、顺时针平均略少转0.14°，偏差多数同向；DONE角度冻结，但下一动作的起始角与前次终态一致。
若路线需要固定航向基准，应使用起始朝向加累计转角作为`TurnToHeading`目标，保持`Turn`本身的相对当前朝向语义。
2Hz回传无法确定最大的瞬时过冲，外部真实朝向与惯导是否一致仍待确认；本轮仅分析，没有进一步调整参数。
