# 自动路线编排

路线只在 `src/route.cpp` 的 `autonomous_program::RunRoutine()` 编写；菜单A与比赛自动共用同一份动作表。当前工作区2.2.0-dev.1，所有动作都必须显式填写末尾的timeout_ms，不提供默认值；速度等前置参数也必须写全。旧写法漏参数会编译失败。

## 蓝方实车候选

`main` 的 `src/route.cpp` 仍默认执行路线 10 的机构联动演示。蓝方候选保存在 `feat/odometry` 的同一入口。先闭爪，再同时抬臂和前推，到放料高度后松爪。随后倒推贴墙、前进翻 Toggle、绕蓝座夹取黄 Pin + Cup，再转向、推靠放料并后退。遥控器记录一轮 **16.02 秒**，参赛路线待定。

## 单位与方向

距离/坐标为mm，时间/超时为毫秒，电压为V，转速为电机输出轴rpm；540电机rpm对应450轮端rpm，是上限，短段不一定达到。正距离前进、负距离后退，正相对角逆时针、负角顺时针。全局X初始前方、Y初始左方；Turn为相对角，TurnToHeading为惯导绝对朝向。

## 现场示教采点

1. 把车按比赛起摆位置和朝向放好，启动 Bartmoss，在惯导校准时保持静止。首次取得完整编码器和惯导反馈时，车心建立为 (0, 0)，起摆车头为 0°。前方为 +X，左方为 +Y，逆时针为正。进入示教沿用这个原点。
2. 在无场控的本地菜单按方向键上，松键、摇杆回中。用左摇杆前后、右摇杆转向，也可让摇杆回中后手推车轮滚动或原地转动车身。底盘此时使用 coast。侧向拖滑、抬车搬动的位移无法由驱动轮编码器测出。
3. 到目标姿态短按 A。遥控器显示实时 X/Y、朝向 H、已记录的点数 P 和记点结果。每次按下只记一个点，按键时刻的朝向也会保留。每次运行可记 64 点，点存在主控内存中。停车长按 B 一秒回菜单，再进示教可以续记或重发。重启程序会清空点表并重新建原点。
4. 遥控器经 USB 连接电脑，VS Code 的 VEX 插件选中设备。在仓库根目录运行 `node scripts/capture-teach.mjs`（Node.js 22 或更新），看到已连接后，在示教模式按方向键右。无需开启 Y 日志。导出每秒两点；在提示保存成功前保持示教模式。缺包可再按右键重发整表。电脑只在收到完整点表后写入 `build/data/teach-points-*.csv`，列为 `point,x_mm,y_mm,heading_deg`。

例如采得第一个点 (300, 150, 90°)，在同一起摆坐标系下可写 `MoveToPoint(300, 150, 300, 200, 5000)`。如果该站要求车头朝采样方向，在它后面接 `TurnToHeading(90, 200, 3000)`。示教只采集按键位置，中间运动由所选路线动作决定。

## 当前动作接口

| 调用示例 | 行为 |
| --- | --- |
| `DriveStraight(500, 540, 5000)` | 前进500，最高540rpm，最多5秒，带航向保持，到位停稳 |
| `Turn(90, 540, 3000)` | 原地相对左转90度，最多3秒 |
| `TurnToHeading(90, 540, 3000)` | 最短方向原地转到IMU朝向90度，最多3秒 |
| `DriveCorner(500, 90, 500, 540, 8000)` | 旧曲率圆角：前直线、一次移动转弯、后直线，共最多8秒 |
| `MoveToPoint(500, 300, 540, 300, 10000)` | 按推算位姿先原地转向再直行，直行/转向上限分别540/300rpm，整个命令最多10秒 |
| `MoveToWaypoint(470, -350, 300, 250, 10, 6000)` | 走到绕行点并停稳，第五个参数是直行结束后的验收半径（mm），第六个是整项超时（ms） |
| `ReverseToPoint(1328.8, -966.4, 540, 300, 6500)` | 用当前位姿将车尾对准目标，再以负距离直行，沿用到点验收与整项超时 |
| `Swing(90, drive::pivot_side::left, 300, 4000)` | 左侧制动，另一侧驱动转90度，最多4秒；可选right |
| `DriveTurnDrive(500, 90, 500, turn_mode::rolling, 150, 540, 5000)` | 直行/移动转向/直行，入角请求150mm/s，命令最多5秒 |
| `PushFor(1000, 4.0, 3000)` | 4V向前推1秒，然后撤压确认停稳；包含停稳共最多3秒 |
| `PushFor(350, -3.0, 2000)` | 车尾以 3 V 后推 350 ms 贴墙，随后撤压并确认轮速已降下来；时间和电压需按起推距离实测 |
| `Wait(200, 1000)` | 停车等待200ms，最多允许1秒 |

## 必填超时的含义

动作提前完成即推进，不等待用完预算。预算有限且必须大于0，0、负数、NaN、无穷值均被拒绝。达到上限仍未完成报TIMEOUT，全路线立即撤输出，后续动作不执行；非法上限在起步前拒绝。控制周期为离散采样，停车发生在首次检测到超时的控制周期。

MoveToPoint的预算覆盖转向和直行，DriveTurnDrive(stop)覆盖完整三阶段；切换内部阶段不重新计时。Wait的执行时长与超时是两个独立参数；Wait(200,200)在正常周期刚好完成可以成功，但预算留余量能避免控制调度迟到导致超时。PushFor的预算还包含撤压后的停稳阶段，不能把1000ms推动时长当作完整执行预算。原控制器的反馈、离线、内部超时等保护仍可更早终止动作，显式timeout是额外的命令执行上限，不会取消已有保护。

```cpp
void autonomous_program::RunRoutine() {
  using namespace route;
  RunRoute({
      DriveStraight(500, 540, 5000),
      Turn(90, 540, 3000),
      DriveStraight(300, 400, 5000),
      PushFor(800, 4.0, 3000),
      Wait(200, 1000),
      DriveStraight(-200, 300, 5000),
  });
}
```

## 多弯全程衔接

专用RollingSquare已移除，相邻rolling组合由一个控制器整块规划，中途不重置速度环、不等待零速。原Turn始终原地转向。

```cpp
RunRoute({
    DriveTurnDrive(500,  90, 600, turn_mode::rolling, 150, 540, 5000),
    DriveTurnDrive(  0, -90, 400, turn_mode::rolling, 150, 540, 4000),
    DriveTurnDrive(  0,  30, 500, turn_mode::rolling, 150, 540, 4000),
});
```

执行直行500→左转90→直行600→右转90→直行400→左转30→直行500，整块末端才停车。上一项after和下一项before相加，后续before填0就直接接续，不多走一段。每项预算从自己的before开始，到自己的转向和after完成结束；上一项after结束时才开始下一项计时，预算不因多个弯相邻而合并或取消。共享直线不停车，到达两个命令距离边界时只切换计时。最后一项还包含末端停稳验收。

每弯可分别填写角度、入角mm/s、最高rpm和timeout。规划向后传播减速与响应距离预算，并向前限制短段加速；入角值是请求上限，短段实际规划可以更低。目标朝向相对连续块起步朝向累加；允许内侧轮反转。直线长度不含转向带来的额外位移，移动转向与零速直角路线的几何终点不同。

插入Turn、Wait、stop组合或独立DriveStraight/DriveCorner/MoveToPoint/Swing/PushFor都会结束前一连续块并先停车；后续rolling另起一块。全程不停应把中间直线写进rolling组合参数，不插独立动作。

单块最多16弯，超过报ROLL TOO LONG。整块起步前检查所有参数，包括后续项的超时；负距离、非零以外或绝对值超过180度的转角会拒绝。最后after须大于位置容差（目前5mm），否则ROLL END DIST；前/中间距离可0。当前4号路线用四条通用组合，150mm/s入角、540rpm上限，每项显式5000ms预算；ROLLING_ROUTE=false恢复原零速转路线。新超时预算尚待实车复核。

## 位姿与物理定位

MoveToPoint按主循环提供的编码器+IMU位姿工作，先原地转向、再固定航向直行，不按横向终点误差动态转向。终点推算距离超过5mm报POINT ERROR，定位失效/过期200ms报POSE ERROR。没有独立里程计，纯横向侧滑不可观测；推算坐标不能代替外部尺量，现有高速点位偏差仍待整定。点位补角尺度、直线240/240rpm/s等参数在performance-config.h，普通Turn不受点位容差缩放影响。

Swing 固定侧使用主动制动，受外力仍可能移动。PushFor 在 0～5000 ms 内向两侧输出相同的固定电压，正值向前、负值向后，幅值为 0.001～12 V。到时撤压并确认轮速停稳。它不控制航向，也不检测接触或重置位姿。

## 启动、取消与回传

用户自行从VS Code下载程序；惯导校准完成后，菜单Y按需开回传、A选自动，松键且摇杆回中后运行一次。B/摇杆可取消，停车长按B一秒回菜单重选。接场控后由比赛权限接管，同一动作表在自动时段执行，禁用立即撤输出，比赛关闭回传。

本地A自动入口统一要求硬件反馈、停车状态和位姿均有效；定位失效锁存显示POSE RESET:RESTART，需将机器人放回已知起点后重启。X模式中的距离/转向单项仍按自身反馈验证，不以全局位姿失效禁止测试。场控许可仍独立于本地菜单，MoveToPoint在执行层保留定位有效性检查。

遥控器在自动结束后显示路线总耗时。从首个动作开始计时，包含途中等待，并行动作的重叠时间只算一次。回到手动后仍可查看上一轮结果。

不要在RunRoutine里调用阻塞vex::wait或直接写电机；使用Wait动作让采样、取消和场控继续响应。动作表在一次运行中保持固定。

DRA记录步骤/result（0空闲、1运行、2DONE、3取消、4故障），具体原因显示于遥控器；连续块完成后步号按命令数推进，内部进度看DRL的completed_turns/total_turns。DRL写rolling.csv，segment_remaining_mm为当前直段余量；旧DCR写corner.csv，remaining_mm为旧圆角全程余量。DVL记录速度环，DPO记录推算位姿。高速回传保持最多2Hz，不能据此排除短于采样间隔的停顿。


## MoveToPoint与Swing分项实车验证

路线7为单条MoveToPoint(300,300,400,300,10000)：起点前方300mm、左方300mm，直行/转向上限400/300电机rpm，总预算10秒。先在地面标记机器人中心起点、初始正前方和目标，启动程序建立坐标后运行一次。到位观察DONE/POINT ERROR/TIMEOUT，并实际测量中心距目标的偏差，不以推算坐标替代尺量。重复测试若搬动车辆复位，应重新启动程序建立原点并完成IMU静止校准。

路线8为Swing(90,left,300,5000)，左侧制动、右侧驱动逆时针90度；9为Swing(-90,right,300,5000)，右侧制动、左侧驱动顺时针90度。两条都只执行单个动作，便于观察固定侧是否滑移、实际角度和停稳；新参数左右各有一轮DONE，重复性待验证。当前默认10号机构路线，复测点位时手动切7号，再按需切8/9号，编译后由用户下载；不自动下载/运行。原0～6号路线保留。


## swing1：Swing尾段整定候选

仅路线Swing通过performance-config.h的SwingControl取独立配置：SWING_POSITION_FEEDBACK_SCALE=4，将原角度反馈3→12、规划结束后的反馈6→24；SWING_RATE_DAMPING=1.4，将角速度误差阻尼0.1→1.4。该参数配对使用，增强追赶同时抑制超调；不是只提高最低转速。原角加减速1200/1000度每秒平方、100ms制动预留、最低60/30rpm、0.8度/2.5度每秒/5rpm到位标准、自动0ms确认、最高转速和显式timeout保持。普通Turn、MoveToPoint转向和移动转向控制器不经过SwingControl。

576组正反角/两侧/100与300rpm/响应/摩擦/轮距模型全部完成，平均总耗时1832→1761ms、从首次进入最后6度到DONE的平均时间457→417ms，17组比原来慢超过20ms；另36组缓存反馈/100/300/540rpm模型通过。这些模型不是对2Hz实车数据的精确辨识，不能承诺每次加快或把实际0.8秒补角减半。未提高最低补角转速，以减少尾段冲过再修回的风险。

右固定swing1单轮实测1273ms，原1513ms；停后误差约0.30度，原约0.54度。8号左固定Swing(+90,left,300,5000)新参数亦单轮DONE：1273ms（原1524ms），停后误差约0.51度（原0.20度）。两侧速度改善、左侧停后误差稍增，重复性尚待验证。对比总时长、规划后耗时、停后角度以及固定侧表现；不要只比较规划结束时刻。恢复旧配置可将反馈尺度设1、阻尼设0.1。新参数尚待实车验证。


## point3：转后方位复核

此前路线7的目标(300,300)，推算终点(304.70,293.18)，径向8.28mm超5mm；原地转向阶段推算中心已前移约8mm。旧流程转后只更新距离，直行仍沿当时朝向，可能导致“新距离、旧方位”的横向误差。

point3在转向完成后用最新位姿重算目标方位；若当前朝向不满足按距离分配的角度预算，则仍在原地转向阶段重新对准。PointControl.max_heading_realignments默认2，0禁用用于旧行为对照，超过2拒绝配置；最多两次后仍不满足报POINT ALIGN停车。全部对准和直行共用调用时填写的timeout，不重新计时。

朝向预算仍为min(原转角容差,atan2(2.5mm,剩余距离))；直行仍按编码器距离和固定起步航向执行，中间不根据横向残差动态转向，不在终点追加转向/直行重试，不放宽5mm判据或改写定位坐标。转向中心重复移动或行驶中跟踪/侧滑仍可能导致POINT ERROR；这不是保证任意场地5mm定位的补丁。

该修正保留在7号路线MoveToPoint(300,300,400,300,10000)，与此前失败轮同目标和速度；当前默认10号，复测时再切7号。用户自行下载，启动时标记中心起点和朝向，运行后检查状态并尺量终点；复位搬车后需重启建立坐标。修正仅软件模型通过，等待实车采集。


## 机构与底盘并行

并行是同一主循环更新多个状态机，不另开电机控制线程。已发布底盘基线v2.1.0-beta.2保留；当前新增接口如下，所有预算均必填：

| 接口 | 行为 |
| --- | --- |
| `StartMechanism(channel, preset, timeout_ms)` | 启动机构后立即执行下一条路线指令；后台动作独立计时 |
| `WaitMechanism(channel, timeout_ms)` | 等待已启动机构完成；等待预算不会重置机构原预算 |
| `DriveStraightWithTrigger(distance_mm, maximum_rpm, trigger_mm, channel, preset, mechanism_timeout_ms, timeout_ms)` | 本段直行到指定行程时启动机构；直行与触发后的机构分别计时 |
| `LiftTo(target_deg, timeout_ms)` | 以相对启动零点的平均电机角度启动抬升，与后续底盘动作并行 |
| `ClawOpen(duration_ms, volts, timeout_ms)` | 以指定电压张开夹爪；时间结束只表示结束通电 |
| `ClawClose(duration_ms, volts, timeout_ms)` | 以指定电压闭合夹爪；时间结束不能证明夹住物体 |
| `ClawClose(duration_ms, volts, hold_volts, timeout_ms)` | 定时闭合后以 `hold_volts` 持续夹紧，直到后续开爪、取消或自动结束 |

channel使用`mechanism::channel::arm/claw/piston`。抬升和夹爪后端已绑定，编号在`mechanisms::preset`中定义：`lift_start`回启动零点、`lift_raised`抬到240电机度、`claw_open/claw_close`以6V通电200ms。目标角度、速度反馈和末段补力参数集中在`include/mechanisms.h`。piston仍无自动适配器，不能直接加入路线。直行触发仅支持独立直线，本段倒车时trigger_mm同样填非负行程；必须不超过本段距离绝对值。零点立即触发；末端触发允许原直行到位容差，不保证精确到某一毫米。尚未扩展到rolling内部或MoveToPoint内部阶段。

```cpp
// main 的路线 10 演示闭爪等待和抬升/直行并行。
using namespace route;
using mechanism::channel;
RunRoute({
    ClawClose(500, 12.0, 1000),
    WaitMechanism(channel::claw, 1000),
    Wait(500, 1000),
    LiftTo(100, 6000),
    DriveStraight(300, 540, 5000),
    ClawOpen(300, 12.0, 1000),
});
```

三个直接参数动作与StartMechanism共用同一个机构调度器，启动成功后立即执行下一条命令；LiftTo不隐式等待抬升到位，需要先抬好再行驶时，在它后面加`WaitMechanism(channel::arm, timeout_ms)`。ClawOpen/Close与压缩包版本相比新增必填的中间参数volts（0～12范围内且大于0），末尾仍为timeout，省略不编译；不会将同事的12V变成全局默认值。原具名预设仍为6V/200ms，直接动作后调用预设也恢复6V。直行距离触发目前仍使用具名预设。

机构与路线等待统一截止边界：恰好在timeout时刻满足完成条件可以DONE；截止时尚未完成，或超过预算后才检查到完成，均报TIMEOUT并撤压。预算应给调度和机械响应留余量；该边界只影响完成判定，不会延长动作预算。

原0～9号测试路线保留。10号将原先从闭爪起等待1000ms拆成“确认500ms闭爪结束，再等待500ms”，启动失败不会进入等待或直行。路线末端会等待抬升和开爪全部结束；夹爪DONE只表示定时动作结束。原抬升独立线程、Y触发抬升和本地自动开回传不接入，Y仍开关LOG。主控屏幕显示抬升零点/当前角度/目标/状态和夹爪电压/时长/状态，沿用低频显示与mutex整包快照。

同一机构运行时再次启动报MECH BUSY，不静默覆盖。启动未绑定后端报MECH NOT BOUND；触发直行会在起步前拒绝未绑定或忙通道。等待从未启动的机构报MECH NOT STARTED。Wait只是路线定时等待，期间后台机构继续更新；不同于WaitMechanism。路线末端若仍有后台动作，会自动等待其完成，原机构timeout继续生效；不会直接DONE或无限等待。机构超时/故障会撤销底盘和其他机构，终止路线，后续命令不执行。普通取消、手控接管、场控禁用和来源切换同样取消后台动作，已取消的距离触发不会延迟执行。

### 同事需要实现的适配接口

在`include/mechanism-control.h`中定义了`mechanism::controller`：

- `Start(int preset, double timeout_ms, double now_ms)`：非阻塞启动，返回是否接受；预算由路线原样传入，成功后Info为running或done。
- `Update(double now_ms)`：每周期使用主循环提供的当前反馈快照更新计算，不能阻塞等待或自行写电机；已完成但需要保持的控制器也会继续收到Update，直到路线结束。
- `Info()`：返回state、不可变静态reason字符串和output。故障返回error；运行时电机离线等保护由真实适配器检测并上报。不能返回指向局部字符串或可变缓冲区的reason。
- `Cancel()`：必须幂等、立即清零电压并选定停止方式，不得在取消过程中产生运动；调度器还会再次强制清零。气动取消保留最后输出，不自动翻转。

输出`motor_mV`范围-12000到12000，手臂正方向仍受ARM_UP_DIRECTION和电机reversed统一处理，夹爪按现有电机配置的正方向；适配器应自行明确正方向。气动通道只能输出piston布尔值且motor_mV必须为0。停止方式使用`manual::stopping::configured/coast/brake/hold`，分别沿用现配置/自由滑行/制动/保持；无电压的完成状态可指定停止方式，取消状态可以采用另一种；路线正常完成会撤压并保留完成停止方式，取消/故障则采用Cancel返回的停止方式。调度器不预设手臂PID、目标角度或归零方法。

main完成Autonomous.ConfigurePoint后已绑定静态ArmController和ClawController；硬件反馈由主循环读取，先Observe再调度Update。适配器生命周期覆盖整个程序，只允许路线未运行时绑定，同一实例不能绑定多个通道，不改变已有hardware::Apply统一写入点。

自动抬升以启动首次有效反馈为零点，启动前须把手臂放在机械起点；断线恢复后需要重新摆回起点并重启。两台电机用同一电压，安装方向由现有ArmL/ArmR反转配置处理。抬升范围0～600电机度，自动上升上限6V、下降上限2.5V，到位或取消后保持。手控R1/R2为12V/4V。夹爪预设开合均为200ms、6V，直接动作的电压、时长和可选夹紧电压由路线填写。手控夹爪为6V。毫米高度入口需先完成三点实测标定。

### 模拟验证与限制

`tests/mechanism-route-test.cpp`用模拟控制器检查并行调度；`tests/mechanism-backend-test.cpp`检查真实机构算法的零点/电压/到位/保护；`tests/direct-mechanism-test.cpp`检查固定机构组合、首周期闭爪、12V后预设恢复6V、并行与末端等待、超时/离线/取消联动。按需定义BARTMOSS_IMPORTED_ROUTE并链接src/route.cpp可复核当前10号路线，已执行一次；该专项不常驻完整回归，避免后续修改路线参数产生误报。常驻current-route检查只验证实际路线的启动与禁用，不强加旧路线参数。测试不编入固件，模型通过不等于实车验收。
